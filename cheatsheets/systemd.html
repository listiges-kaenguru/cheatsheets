Dienste steuern

BefehlBeschreibung
systemctl status dienstStatus mit den letzten Logzeilen
sudo systemctl start dienst / sudo systemctl stop dienstDienst starten / stoppen
sudo systemctl restart dienstDienst neu starten
sudo systemctl reload dienstKonfiguration neu laden (wenn vom Dienst unterstützt)
sudo systemctl reload-or-restart dienstNeu laden, sonst neu starten
sudo systemctl enable --now dienstBeim Booten aktivieren und sofort starten
sudo systemctl disable --now dienstDeaktivieren und sofort stoppen
systemctl is-active dienst / systemctl is-enabled dienstLäuft er? / Startet er beim Booten? (für Skripte)
sudo systemctl mask dienst / sudo systemctl unmask dienstStart komplett verhindern / wieder erlauben
sudo systemctl kill -s HUP dienstSignal an alle Prozesse des Dienstes senden
systemctl --failedFehlgeschlagene Units
sudo systemctl reset-failedFehlerstatus zurücksetzen
systemctl list-units --type=service --state=runningLaufende Dienste
systemctl list-unit-files --state=enabledAktivierte Units
systemctl list-timers --allTimer mit nächster Ausführung
systemctl --user status dienstBenutzerdienste (ohne root)

Unit-Dateien

BefehlBeschreibung
/etc/systemd/system/Eigene und überschriebene Units (höchste Priorität)
/usr/lib/systemd/system/Units aus Paketen (nicht direkt bearbeiten)
~/.config/systemd/user/Benutzer-Units
systemctl cat dienstUnit inkl. Overrides anzeigen
sudo systemctl edit dienstDrop-in-Override anlegen (bleibt bei Updates erhalten)
sudo systemctl edit --full dienstKomplette Kopie der Unit bearbeiten
sudo systemctl daemon-reloadGeänderte Unit-Dateien einlesen
systemctl show dienst -p MainPID,RestartEinzelne Eigenschaften anzeigen
systemd-analyze verify datei.serviceUnit-Datei auf Fehler prüfen
systemd-analyze security dienstHärtung eines Dienstes bewerten
Beispiel: /etc/systemd/system/meineapp.service
[Unit]Allgemeiner Abschnitt
Description=Meine AnwendungBeschreibung
After=network-online.target / Wants=network-online.targetErst nach bestehender Netzwerkverbindung starten
[Service]Dienst-Abschnitt
Type=simpleTyp: simple, exec, forking, oneshot, notify
ExecStart=/usr/local/bin/meineappStartbefehl (absoluter Pfad)
User=meineapp / Group=meineappUnter eigenem, unprivilegiertem Benutzer ausführen
WorkingDirectory=/opt/meineappArbeitsverzeichnis
EnvironmentFile=/etc/meineapp.envUmgebungsvariablen aus Datei
Restart=on-failure / RestartSec=5Bei Fehler nach 5 s neu starten
NoNewPrivileges=yes / ProtectSystem=strict / PrivateTmp=yesEinfache Härtung
[Install]Installations-Abschnitt
WantedBy=multi-user.targetBeim normalen Systemstart aktivieren

Timer (Cron-Alternative)

BefehlBeschreibung
Beispiel: /etc/systemd/system/backup.timer (startet backup.service)
[Timer]Timer-Abschnitt
OnCalendar=*-*-* 02:00:00Täglich um 2 Uhr
OnCalendar=Mon..Fri 08:00Werktags um 8 Uhr
OnBootSec=5min / OnUnitActiveSec=1h5 min nach Boot / stündlich danach
Persistent=trueVerpasste Läufe nachholen
RandomizedDelaySec=10minZufällige Verzögerung
[Install] / WantedBy=timers.targetTimer aktivierbar machen
sudo systemctl enable --now backup.timerTimer aktivieren
systemd-analyze calendar 'Mon..Fri 08:00'Zeitausdruck prüfen, nächste Termine anzeigen
systemd-run --on-active=30m befehlEinmalig in 30 Minuten ausführen

Logs (journalctl)

BefehlBeschreibung
journalctl -u dienstLogs eines Dienstes
journalctl -u dienst -fLive verfolgen
journalctl -xeu dienstLetzte Einträge mit Erklärungen (bei Startfehlern)
journalctl -n 100Letzte 100 Einträge
journalctl -b / journalctl -b -1Aktueller / vorheriger Boot
journalctl --list-bootsVerfügbare Boots
journalctl --since "1 hour ago"Letzte Stunde
journalctl --since "2026-01-01 08:00" --until "2026-01-01 12:00"Zeitraum
journalctl -p err -bNur Fehler und schwerer im aktuellen Boot
journalctl -kKernel-Meldungen
journalctl _PID=1234Nach Prozess-ID filtern
journalctl -g 'muster'Nachrichten per Regex durchsuchen
journalctl -o json-prettyAusgabe als JSON
journalctl --disk-usageSpeicherbedarf der Logs
sudo journalctl --vacuum-time=14d / sudo journalctl --vacuum-size=500MAlte Logs löschen
