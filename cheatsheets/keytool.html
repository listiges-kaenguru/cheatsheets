Grundlagen & Anzeigen

keytool gehört zum JDK ($JAVA_HOME/bin). Seit Java 9 ist PKCS12 der Standard-Keystore-Typ; JKS gilt als veraltet. Einträge werden über ihren -alias angesprochen. Fehlt -storepass, fragt keytool interaktiv nach dem Passwort.

BefehlBeschreibung
keytool -help / keytool -genkeypair -helpÜbersicht aller Befehle / Optionen eines Befehls
keytool -list -keystore keystore.p12Einträge auflisten (Alias, Typ, Fingerabdruck)
keytool -list -v -keystore keystore.p12Ausführlich: Aussteller, Gültigkeit, Erweiterungen, Kette
keytool -list -v -keystore keystore.p12 -alias serverNur einen Eintrag anzeigen
keytool -list -rfc -keystore keystore.p12 -alias serverZertifikat(skette) als PEM ausgeben
keytool -printcert -file server.crtZertifikatsdatei anzeigen (PEM oder DER)
keytool -printcert -sslserver example.org:443Zertifikatskette eines TLS-Servers anzeigen
keytool -printcert -sslserver example.org:443 -rfc > chain.pemServerkette als PEM speichern
keytool -printcertreq -file server.csrZertifikatsanforderung (CSR) anzeigen
keytool -printcrl -file ca.crlSperrliste (CRL) anzeigen
keytool -J-Duser.language=en -list -keystore keystore.p12Ausgabe auf Englisch (hilfreich beim Suchen nach Fehlermeldungen)

Schlüsselpaare & CSRs

BefehlBeschreibung
keytool -genkeypair -alias server -keyalg RSA -keysize 3072 -validity 365 -keystore keystore.p12 -dname "CN=example.org, O=Firma, C=DE" -ext "SAN=dns:example.org,dns:www.example.org"RSA-Schlüsselpaar mit selbstsigniertem Zertifikat und SAN erzeugen
keytool -genkeypair -alias server -keyalg EC -groupname secp256r1 -keystore keystore.p12EC-Schlüssel (P-256) erzeugen, fragt Namen interaktiv ab
keytool -genkeypair -alias server -keyalg Ed25519 -keystore keystore.p12Ed25519-Schlüssel (ab Java 15)
-ext "SAN=dns:example.org,ip:192.0.2.10"Subject Alternative Names (DNS-Namen, IP-Adressen)
-ext KU=digitalSignature,keyEncipherment -ext EKU=serverAuthSchlüssel- und erweiterte Verwendung festlegen
-ext BC:c=ca:trueAls CA-Zertifikat markieren (Basic Constraints, kritisch)
-sigalg SHA256withRSA / -startdate 2026/10/01Signaturalgorithmus / Beginn der Gültigkeit festlegen
keytool -certreq -alias server -keystore keystore.p12 -file server.csr -ext "SAN=dns:example.org"CSR für einen vorhandenen Schlüssel erzeugen (SAN erneut angeben!)
keytool -gencert -alias ca -keystore ca.p12 -infile server.csr -outfile server.crt -rfc -validity 365 -ext "SAN=dns:example.org"CSR mit einer CA aus dem Keystore signieren
keytool -genseckey -alias aeskey -keyalg AES -keysize 256 -keystore secrets.p12Symmetrischen AES-Schlüssel ablegen

Erweiterungen aus -genkeypair werden nicht automatisch in einen CSR übernommen – -ext bei -certreq wiederholen.

Importieren & Exportieren

BefehlBeschreibung
keytool -importcert -alias server -file server-chain.crt -keystore keystore.p12Signierte Antwort der CA installieren – gleicher Alias wie der Schlüssel, ersetzt das selbstsignierte Zertifikat
keytool -importcert -trustcacerts -alias server -file server.crt -keystore keystore.p12Beim Aufbau der Kette auch den Java-Truststore (cacerts) nutzen
keytool -importcert -alias intermediate -file intermediate.crt -keystore keystore.p12Zwischenzertifikat vorab als vertrauenswürdig importieren
keytool -exportcert -alias server -keystore keystore.p12 -rfc -file server.crtZertifikat als PEM exportieren (ohne -rfc: DER)
keytool -importkeystore -srckeystore quelle.p12 -srcstoretype PKCS12 -destkeystore ziel.p12 -srcalias serverEinzelnen Eintrag in einen anderen Keystore kopieren
keytool -importpass -alias dbpass -keystore secrets.p12Passwort als geheimen Eintrag speichern (fragt interaktiv)

keytool kann private Schlüssel weder aus PEM-Dateien importieren noch als PEM exportieren. Dafür den Umweg über PKCS12 und OpenSSL nehmen (siehe Formate konvertieren).

Truststore & cacerts

Java vertraut standardmäßig den CAs aus $JAVA_HOME/lib/security/cacerts (Standardpasswort changeit). Unter Fedora/RHEL und Debian/Ubuntu wird diese Datei aus dem System-CA-Store erzeugt – dort CAs besser systemweit hinzufügen.

BefehlBeschreibung
keytool -list -cacertsEinträge des Java-Truststores anzeigen (ab Java 9)
keytool -list -cacerts -alias firma-rootPrüfen, ob eine bestimmte CA enthalten ist
sudo keytool -importcert -cacerts -alias firma-root -file root-ca.crtEigene Root-CA in den Java-Truststore aufnehmen
sudo keytool -delete -cacerts -alias firma-rootCA aus dem Java-Truststore entfernen
keytool -importcert -alias firma-root -file root-ca.crt -keystore truststore.p12 -storepass geheim -nopromptEigenen Truststore anlegen bzw. erweitern (ohne Rückfrage)
sudo trust anchor root-ca.crtFedora/RHEL: CA systemweit (inkl. Java) hinzufügen
sudo cp root-ca.crt /usr/local/share/ca-certificates/ && sudo update-ca-certificatesDebian/Ubuntu: CA systemweit (inkl. Java) hinzufügen

Einträge & Passwörter verwalten

BefehlBeschreibung
keytool -delete -alias server -keystore keystore.p12Eintrag löschen
keytool -changealias -alias alt -destalias neu -keystore keystore.p12Alias umbenennen
keytool -storepasswd -keystore keystore.p12Keystore-Passwort ändern
keytool -keypasswd -alias server -keystore keystore.jksSchlüsselpasswort ändern (nur JKS/JCEKS)
-storepass:env KS_PASS / -storepass:file pass.txtPasswort aus Umgebungsvariable / Datei lesen (nicht in der Shell-Historie)
-storetype PKCS12 / -storetype JKSKeystore-Typ explizit angeben
-nopromptRückfragen unterdrücken (für Skripte)
-vAusführliche Ausgabe

Bei PKCS12 haben Keystore und private Schlüssel dasselbe Passwort; -keypass wird dort ignoriert bzw. muss gleich -storepass sein.

Formate konvertieren

BefehlBeschreibung
keytool -importkeystore -srckeystore keystore.jks -srcstoretype JKS -destkeystore keystore.p12 -deststoretype PKCS12JKS nach PKCS12 migrieren
keytool -importkeystore -srckeystore keystore.p12 -srcstoretype PKCS12 -destkeystore keystore.jks -deststoretype JKSPKCS12 nach JKS (nur für alte Software)
openssl pkcs12 -export -in server.crt -inkey server.key -certfile chain.crt -name server -out server.p12PEM-Schlüssel + Zertifikat zu PKCS12 bündeln (danach direkt nutzbar oder per -importkeystore übernehmen)
keytool -importkeystore -srckeystore server.p12 -srcstoretype PKCS12 -destkeystore keystore.p12Gebündelten Schlüssel in bestehenden Keystore übernehmen
openssl pkcs12 -in keystore.p12 -nocerts -noenc -out server.keyPrivaten Schlüssel als PEM aus PKCS12 extrahieren (OpenSSL 3; älter: -nodes)
openssl pkcs12 -in keystore.p12 -nokeys -out chain.pemZertifikate als PEM aus PKCS12 extrahieren
